MapReduce mechanics and retry safety

Map emits key-value records; shuffle groups by key; reduce aggregates each key group.

High yieldProvided module reference

Basis: M2 pp.27–28; MidSem key p.4. Page labels point to the provided files or named reading; the explanation and exercises here are independently written.

01 / Understand

What actually happens?

Data locality makes map-only jobs scalable; shuffle is a network-intensive all-to-all movement. Pure deterministic maps can be retried after crashes. For dedup banding, map each document's band identifier to its docID and reduce each bucket into candidate pairs.

Core principle
Map emits key-value records; shuffle groups by key; reduce aggregates each key group.

Try to reason through the mechanism

  1. Identify what the system is trying to preserve or measure in the situation.

02 / Small example

A concrete case

Signature construction is independently map-only; grouping band buckets requires shuffle/reduce.

Equation or decision rule

map(doc)→(key,value); shuffle by key; reduce(key,values)

03 / Examiner's trap

A tempting answer that fails

Assuming a reduce function is required for every MapReduce job.
