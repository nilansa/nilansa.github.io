RUM conjecture

Data structures trade read, update and memory overhead; no single choice dominates all workloads.

High yieldProvided module reference

Basis: M1 p.55; Quiz-2 case 10. Page labels point to the provided files or named reading; the explanation and exercises here are independently written.

01 / Understand

What actually happens?

An index optimized for faster reads may pay in writes or space. An immutable log favors writes, a B-tree balances sorted lookup and updates, and auxiliary indexes improve reads by using memory and update work. Compare actual workload and cost units.

Core principle
Data structures trade read, update and memory overhead; no single choice dominates all workloads.

Try to reason through the mechanism

  1. Identify what the system is trying to preserve or measure in the situation.
  2. Separate the observed symptom from the cause described in this lesson.
  3. Choose the operation, model or trade-off that fits that cause; name its failure mode.
02 / Small example

A concrete case

A claimed novel datastore is faster to read, write and smaller than all alternatives for all possible workloads: challenge the universal claim.

Equation or decision rule

R = read overhead, U = update overhead, M = memory overhead

Know what each symbol or action means. The instructor's announced final-exam format emphasizes applying principles to short objective scenarios.

03 / Examiner's trap

A tempting answer that fails

Treating a universal three-way win as plausible without workload qualification.

Use an explicit four-part answer: symptom → principle → mechanism → consequence. A strong answer explains why the apparently easy choice is unsafe or incomplete.

04 / Active recall

Exam-style scenario

A database advertises lower read, update and memory costs than LSM for every workload. What is the main caveat?
One-line viva / short-answer question

Why does an extra secondary index have a cost?

It improves some reads but consumes storage and must be updated on writes.
