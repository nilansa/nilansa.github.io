Clicks, A/B tests, and p-values

Follow the boxes. Do one example per section. Start with Clicks → A/B → p-value.

1. A click needs a look first

  1. Show the result
  2. User looks at its slot
  3. If they look, they may click

Examined: Did they look at the slot? Attractive: If they looked, did they click?

Click rate = P(look) × P(click | look)
For 100 shows: 50 look. 20% of those 50 click. That is 10 clicks, so CTR is 10%.

Move the same item down. Now only 25 look. At the same 20% attractiveness, 5 click. Half the clicks does not mean half the relevance.

How do I correct position bias?

Estimate the chance of a look, ideally by randomizing positions. If that chance is 0.25, count a click as 1/0.25 = 4. Give rare looks more weight. Raw click rates alone do not tell you the chance of a look.

Why does sampling change CTR?

10 clicks + 100 non-clicks gives 9.1% real CTR. If you keep only 10 non-clicks, the sample says 50%. To get back to real CTR, restore the missing non-click weight. Calibration asks whether the predicted 10% really means about 10 in 100.

2. A/B: change one thing

  1. Pick the metric and the unit
  2. Randomly assign A or B
  3. Run both at the same time
  4. Check the split, then compare

A uses the old ranker. B uses the new one. Keep each user in the same group if they return. Track orders as the main result and p99 latency as a guardrail.

Example: A gets 100 orders from 1,000 users (10%). B gets 120 (12%). The estimated change is +2 percentage points. An interval tells you how uncertain that estimate is.
Do this before reading the lift: If a planned 50/50 split comes out 58/42, check assignment and missing logs. This is a sample-ratio mismatch.
What if B makes A’s shared server slower?

That is interference. One group’s treatment changes the other group’s result. Use separate server pools or suitable time blocks. Analyze the unit you randomized.

What if B wins interleaving?

A mixed result list favors B in that preference test. It does not show that the full B experience increases orders. Use an A/B test to measure orders.

3. p-value: assume no effect first

  1. Assume A and B have no true difference
  2. Ask how far results could move by chance
  3. Count outcomes at least as extreme

If p = .03, then under the no-effect assumption and the test model, about 3 in 100 repeated tests would give a test result this extreme or more.

Do not flip the condition. This is not a 3% chance that there is no effect. It does not say whether the gain is large enough to matter.

If you chose .05 before the test, .03 is statistically significant. Still check the effect size and its interval.

What if p = .20 and the interval is wide?

You did not show a difference. You also did not prove the effect is zero. If you want to detect half as much improvement at the same variance and power, plan for about four times the sample.

4. Offline tests tell you what to try

  1. Same queries, both rankers
  2. Compare scores query by query
  3. Test the winner online

Offline nDCG asks whether the best judged results are near the top. A real user also waits, clicks, or leaves. If nDCG rises but live clicks drop and p99 doubles, check serving latency first.

How do I compare on the same 100 queries?

For each query, subtract A’s score from B’s score. Test or resample those paired query differences. Do not treat individual documents in one query as independent.

Say this once: A click needs a look. A/B needs independent groups. A p-value assumes no effect. Offline relevance does not include waiting.
