Assignment 3: sanity-first execution plan

The goal is a correct and reproducible benchmark. Test the harness on small data first. Repair errors before you run the full benchmark.

Deadline check: The supplied brief lists 25 October 2026, 23:59 IST. That date has passed. Check the latest Moodle announcement or instructor message before you assume that late submission is accepted.

1. Required work

Data

SIFT-1M: 128 dimensions and Euclidean distance. GloVe-100: about 1.18M vectors and 100 dimensions. Normalize GloVe base and query vectors, then use L2 distance.

Indexes

Build an exact FAISS baseline. Compare HNSW, IVF-Flat and IVF-PQ on both datasets.

Query split

Use the first 5,000 queries to tune. Freeze the settings before you report results on the last 5,000 queries.

Deliverable

Report of at most five pages. Submit one ZIP with the exact required files. Do not include datasets or index files.

2. Workflow gates

  1. Requirements: Read the brief. Confirm the current deadline, allowed libraries, file names and page limit.
  2. Data sanity: Read a small HDF5 slice. Check shapes, data types, finite values, IDs, stored neighbours and GloVe normalization.
  3. Exact baseline: Run FAISS IndexFlatL2. Compare its neighbours with the stored ground truth. Implement tie-aware Recall@10 and test ties at rank 10, duplicate IDs and invalid IDs.
  4. Small index tests: Build HNSW, IVF-Flat and IVF-PQ on a small subset. Test training, adding vectors, querying, saving and loading. Fix failures before you expand.
  5. Timing sanity: Warm up. Run one query at a time on one thread. Repeat each timing and use the median. Time index construction separately. Time exact search one query at a time and in a batch.
  6. Full benchmark: Only after the earlier gates pass, tune on the first 5,000 queries. Freeze the selected settings. Measure the final 5,000 queries once.
  7. Experiments: Write and commit each hypothesis before you run the experiment. Change one factor at a time. Record random seeds and settings.
  8. Package audit: Regenerate report figures and tables from results.csv. Run full and quick commands. Check the ZIP contents and AI-use record.

3. Proposed Part 3 experiment: scaling on SIFT

Test: Repeat the benchmark at 100K, 300K and 1M vectors. Compare exact search, HNSW and IVF-Flat at recall 0.95.

Hypothesis to commit first: “As the SIFT database grows from 100K to 1M vectors, exact search will require more query work. HNSW and IVF-Flat should reduce query work, but the cost of reaching recall 0.95 will depend on their settings and the data size.”

This is a proposed hypothesis, not a measured result. Keep the final query set held out.

4. Proposed Part 4 experiment: synthetic cluster overlap

Question: How does increasing overlap between synthetic clusters affect ANN recall and query speed?

Design: Generate seeded 128-dimensional vectors. Keep the vector count, cluster count, noise level and query method fixed. Change only cluster separation. Use one control and at least three treatment settings. Compare at least HNSW and IVF-Flat.

Hypothesis to commit first: “As clusters overlap more, nearest-neighbour boundaries will become harder to distinguish. Recall at a fixed search budget may decrease, and the effect may differ between graph and cluster-based indexes.”

Use no more than 500,000 synthetic vectors. The hypothesis can be wrong. Explain what the measurements support.

5. Fair benchmark rules

  • Use one machine and record its CPU, RAM, operating system and library versions.
  • Use the same data representation and distance definition for comparable runs.
  • Measure single-query QPS on one thread. Repeat timings and report the median.
  • Measure build time separately. Measure serialized index size and bytes per vector.
  • Save every run in results/results.csv with parameters, recall, QPS, build time, index size and software version.
  • Produce one recall@10 versus QPS plot per dataset. Report QPS at recall 0.90 and 0.95. Say “not reached” if an index does not reach a target.
  • Do not use the ann-benchmarks framework to run your experiments. Do not copy published benchmark numbers.
