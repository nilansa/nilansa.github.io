2. Priority fixes before final acceptance

P0 — Held-out operating-point selection.

The report currently selects the fastest qualifying point using held-out recall and QPS. Parameters should be selected using the first 5,000 queries, then reported unchanged on the final 5,000.

Measured example: on SIFT at recall target 0.90, tune-based HNSW selection gives about 13,377 held-out QPS; retrospective held-out selection gives about 18,216 QPS. Do not report the latter as if selected without looking at final results.

P1 — Metric tests

The existing “tied item at boundary” test replaces a true boundary neighbour with a closer point. Add a genuine boundary-tie swap test. Also add explicit duplicate-ID and invalid-ID tests. Re-run the full test suite in isolation.

P1 — Canonical report and archive

Two ZIPs have identical report and CSV payload bytes but different Git-directory metadata and different overall ZIP hashes. Separate local PDFs also differ in bytes. Check report text and figures, current Git HEAD, file inventory and archive checksums before choosing the canonical submission.

P1 — AI usage record

The existing AI log contains available prompt/response summaries. Its own checkpoint says a complete verbatim chat export is unavailable. Do not claim the log is complete unless every required prompt and response can be accounted for.

P2 — Scientific explanation

The synthetic experiment attributes lower recall partly to reduced distance contrast in higher dimensions. The measurements support falling recall at fixed search effort; a separate contrast statistic would strengthen the proposed mechanism. Avoid claiming this mechanism was measured when it was not.
