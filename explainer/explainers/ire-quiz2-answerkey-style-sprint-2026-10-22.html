How he awards marks

Quiz 1: CAP decisions

Choice → invariant → why

Three marks per subsystem: one for A/C; one for the protected or sacrificed property; one for a valid reason.

Example: Checkout → C → prevents inconsistent locked prices and double charging → reject unsafe writes during partition.

Little’s law

Boundary → formula → assumption

Separate the whole user cycle from the server boundary. He rewards the correct boundary, the equation and steady-state assumption.

Whole loop: N = X(R + Z). Server only: Q = XR.

Midsem: method before result

Set-up → calculation → reason

For MinHash and LSH, marks were allocated to intermediate steps, not solely the final number.

Example: Banding trade-off → higher recall of similar pairs brings more false positives and verification.
