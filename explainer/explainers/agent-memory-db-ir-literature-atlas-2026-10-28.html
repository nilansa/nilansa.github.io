0. What counts as “already done”?

Three match levels

Direct = the newer work reuses a recognizable older algorithm (e.g. Personalized PageRank).

Strong = the same systems decision (e.g. choose which corpus to search), but different implementation/guarantees.

Analogy = similar architecture or motivation, not proof of algorithmic equivalence.

Not all “memory” means the same thing

Storage: persist, revise and retrieve facts. Communication: choose the agent holding evidence, or send work to peers. Policy: select a retrieval/writing action.

Store-level gains, evidence Recall@K, final QA accuracy, agent success and message efficiency are different metrics.

Research integrity: a reused primitive does not automatically invalidate a paper. New workload, semantics, guarantees, constraints, or measurements can be substantial. Likewise, a graph, HNSW or Bloom filter cannot by itself tell whether a natural-language fact exists or is correct.

5. Better-scoped research questions

Experiment A — Does per-query adaptation have headroom?

Question: Can a policy outperform the best single fixed retrieval configuration under equal evidence budget? Use dense, sparse, rerank depth, temporal filtering and optional graph as separate knobs.

R_fixed  = max_c mean_q Recall@10(q, c)
R_oracle = mean_q max_c Recall@10(q, c)
headroom = R_oracle - R_fixed

Only then train a small query router. Test it against Bao-style control and HAMMER / MemAgent novelty threats. Metrics: Recall@10/15, p95 latency, calls, token cost, router error and out-of-domain performance.

Experiment B — Can agent routing inherit classical collection selection?

Question: Does a SIGIR-era collection-selection algorithm applied to agent expertise summaries beat broadcast and dense semantic routing when only a few agents hold an answer?

Control: keep memory contents identical across methods. Vary agent count, ownership skew and overlap; log missed-owner rate, task success, communication tokens and latency. Scope permissions must be enforced before learned routing.

Experiment C — Does version-aware retrieval beat a simple appended store?

Question: When the user corrects a fact, can a versioned structured store answer both “what is true now?” and “what was believed then?” without leaking stale claims? Compare append-only, latest-write-wins, typed versioning and provenance-aware read paths.

Control: use the same extracted facts and answerer; vary only indexing/version-selection. Measure current-fact recall, historical-fact recall, stale-answer rate, correction-to-queryable time and write amplification.

Research recommendation: Start with experiment A as a negative-results-friendly ablation study, and B as a separate communication contribution. Do not build a multi-index neural meta-controller until the oracle gap is nontrivial. The strongest paper may be a careful empirical result showing which query classes need adaptation and which do not.

7. Import / export paper checklists

Extend this bibliography without editing code: choose a JSON or CSV file and the page imports paper rows into your current browser session. Export merged records plus reading progress for later editing or transferring to the canonical repository through a connected GitHub workflow.

Privacy and functionality: This is a static GitHub Pages site. Import means reading a file locally in your browser, not uploading it to a server or GitHub. Nothing is shared automatically. To make an import permanent for everyone, the new JSON must be committed to the repo through an authorized GitHub connector. Do not import secrets.

Accepted JSON & CSV columns
JSON: [{"id":"new-paper-1","title":"Paper title","venue":"SIGIR","year":2026,"cluster":"retrieval","mechanism":"What it does","limit":"Why not identical","url":"https://...","status":"peer-reviewed"}]
CSV: id,title,venue,year,cluster,mechanism,limit,url,status

Allowed clusters: write, retrieval, hierarchy, adaptive, communication, governance, benchmark. Duplicate IDs will be skipped rather than overwriting curated entries.

8. Audit, provenance & limitations

All paper-title links in the checklist open the paper or a publisher/conference page. Historical mappings cite the older proceedings directly. Conference acceptance is distinguished from arXiv manuscripts, publisher issues and workshop/Findings tracks.

As of 28 October 2026, this is a deliberately curated first-pass atlas, not a systematic review of every paper accepted at SIGMOD, VLDB, ICDE, SIGIR, ACL, EMNLP, ICLR, ICML or NeurIPS. Paper abstracts are simplified; verify exact experimental setup and claims from the PDF before writing related work. Some papers have similar names (the two AtomMem papers); they are kept separate. MemForest is a 2027 VLDB submission, not called an accepted 2026 VLDB paper.
