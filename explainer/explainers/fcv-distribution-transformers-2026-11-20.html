Two meanings of “transformer” in the same book

Foundations of Computer Vision is by Antonio Torralba, Phillip Isola, and William T. Freeman (MIT Press, 2024; print ISBN 9780262048972). In the authors’ online book, Chapter 13 explains how an ordinary neural network transforms a distribution of examples. The attention-based architecture is Chapter 26, Transformers. The first idea helps build intuition for the second, but they are not the same chapter or claim.

Chapter 13: What changes from layer to layer?

Picture each example as a dot. Two measured features give each dot an x and a y coordinate. A learned linear layer can rotate or stretch this cloud; a nonlinear step can fold it. Repeat until a simple output layer can tell the classes apart. The examples have not changed. The network has changed the coordinates it uses to describe them.

Work a case. Suppose “same sign” is the positive class. Points (1, 1) and (−1, −1) are positive; (1, −1) and (−1, 1) are negative. No single straight line separates them. A hidden layer can compute ReLU(x+y) and ReLU(−x−y), then add them. The new score is |x+y|: 2 for positives and 0 for negatives. A threshold at 1 now works. In a real net the optimizer learns useful transformations rather than being given these weights.

Loss versus metrics. A classification loss gives the optimizer a score for each prediction. For example, cross-entropy penalizes assigning low probability to the true class. Precision and recall summarize decisions after selecting a threshold. Two models can have identical precision and recall but assign very different probabilities to those decisions. You can follow the forward pass now; Chapter 14 explains how backpropagation uses the chain rule to find how changing each weight would change the loss.

Chapter 26: What does attention add?

For an image, split the RGB grid into patches. Flatten each patch and project it to a learned feature vector, or token. Provide position information so the model can distinguish the same patch placed elsewhere. Each attention head makes three views of every token: a query says what it is looking for, a key says what it can match, and a value carries the information it can pass on. These are learned projections, not hand-written labels.

  1. Mix across positions. For a query, compare its vector to all allowed keys using dot products. Scale the scores, turn them into weights with a softmax across keys, and average their value vectors using those weights. Different heads can learn different similarity rules, but do not assume that a head always has one human-readable job.
  2. Mix within a position. The same small feed-forward network (MLP) acts separately on each updated token. This changes its features without reading other tokens. Layer normalization rescales features within each token; it does not mix tokens across positions.
  3. Make a correction, not a replacement. A typical vision block adds the attention output back to its input, then adds the MLP output back to the resulting token. A branch can learn a small correction or nearly zero. The shortcut gives information and training signals a direct route, but it does not guarantee that no information is lost. Many vision blocks normalize before each branch. The original 2017 Transformer and modern variants may place normalization differently.

Why divide by the square root of key width? If the components are roughly independent, centered, and unit-scale, a dot product over dk coordinates has variance about dk. Its typical magnitude therefore grows like √dk. Without scaling, higher-dimensional scores can push softmax toward a single winner before the model has learned a useful match. Dividing by √dk keeps the typical score near a comparable scale. This is not cosine similarity: we do not divide by each vector’s own length.

Trace the shapes with one image

Ignore the batch dimension and use mean pooling rather than a class token. An 8 × 8 RGB image yields four 4 × 4 patches. Each patch has 48 numbers. Choose token width 8 and two heads of width 4.

One toy query sees raw scores [4, 2, 0, 0]. Here √4 = 2, so it uses [2, 1, 0, 0], giving weights about [0.61, 0.22, 0.08, 0.08] after rounding. Those weights mix four value vectors, not the keys. In a usual image encoder, patches can read other patches in both directions; a next-token language decoder uses a mask to block future positions.

Check yourself

If you remove attention but keep the per-token MLP, features within a patch can still change. Before pooling, however, one patch cannot directly use the evidence from another. If you remove positions but retain ordinary unmasked attention, permuting input rows simply permutes output rows; with mean pooling the final representation cannot tell patch arrangements apart.

Chapter 13, section by section

  1. 13.1 · Change viewpoint. Follow a set of examples through one layer at a time, not just the output score for one image.
  2. 13.2 · Draw a mapping. Put input and output on separate number lines. The identity leaves every point where it was. ReLU sends every negative coordinate to zero; it can merge distinct inputs.
  3. 13.3 · Compose layers. An affine map can shift, stretch, or rotate points. A nonlinearity can collapse regions or bend the mapping. Stacking just affine maps would still give one affine map.
  4. 13.4 · Read a classifier geometrically. The model can transform a data distribution so a linear head works even when one straight line failed in the raw coordinates. Lower training loss is evidence of fitting, not a guarantee that separation transfers.
  5. 13.5 · Scale the mental model. Hidden representations are high-dimensional, but each image still has one coordinate vector at a layer. ReLU may make many coordinates zero. A two-dimensional projection can help you see a pattern without proving that it dominates every direction.
  6. 13.6 · Carry one idea forward. When reading a new architecture, ask what change each block can make to the features. An attention block can move them using information from other tokens; a per-token MLP acts on each token's features separately.
