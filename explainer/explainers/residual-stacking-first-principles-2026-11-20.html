Residual stacking: keep the current representation, then edit it

Suppose a model already has features x. A plain layer must learn the entire next representation, H(x). What if the useful answer is “mostly keep what I have”? We can write the desired change as F(x) = H(x) − x and build the layer to return y = x + F(x). During training, F is still learned from the model’s usual end-to-end loss. Nobody needs to supply a label for each layer’s “correct edit.” If the branch outputs zero, this block already knows how to copy.

What stacks, and what cancels?

Use two illustrative features with input x₀ = (2, 1). Block 1 produces change (+1, −0.5), giving x₁ = (3, 0.5). Block 2 sees that updated state and produces (−1, +0.25), giving x₂ = (2, 0.75). The first-coordinate edits cancel; the net second-coordinate edit is −0.25. In an identity-skip stack, x₂ = x₀ + F₁(x₀) + F₂(x₁). This is not the same as evaluating all edits on x₀ independently.

Adding requires compatible shapes. If the block changes feature width or resolution, a shortcut can project the input, y = P(x) + F(x), for example with a strided 1×1 convolution in a ResNet. Both paths must land in the same output shape. With F(x)=0 this block returns P(x), not necessarily x; projection can discard information.

Why the shortcut can help training

In a plain stack, the gradient must traverse every learned transformation. In an identity-skip block without an after-addition transform, its local Jacobian is I + JF: one gradient contribution comes through the identity, the other through the learned edit. With F(x)=0.1x the scalar local derivative is 1.1, not 0.1. This is a useful route, not a guarantee: F(x)=−x cancels it exactly, and gradients can still shrink or grow over many layers. Post-addition normalization or activation also changes the local derivative.

Transformer sublayers: where does normalization go?

Take F to be attention or a feed-forward network. For a pre-norm sublayer, y = x + F(LN(x)): normalize the branch input and add the result to the untouched shortcut. For a post-norm sublayer, y = LN(x + F(x)): normalize after adding, as in the original Transformer. With a zero branch, pre-norm returns x at this sublayer; post-norm generally returns LN(x). A Transformer block usually applies the relevant pattern separately for attention and the feed-forward network; an implementation can also add a final output norm.

Three different things called a “residual”

Residual neural block
An internal feature update, x + F(x). The branches are usually trained together; there is no explicit stage-by-stage target y − ŷ.
Gradient boosting
An update to the current prediction function. Fit a new learner to the negative gradient of the loss at the current predictions, then add a scaled version of that learner. For squared error this target is proportional to the familiar y − ŷ; for other losses it need not be that difference.
Ceous test-time offset
Think of a base representation plus a temporary correction, schematically q′ = q + Δq. This resembles the form of a residual update. It is a test-time change to a particular query representation, not a learned architectural shortcut in every layer and not a new weak learner fitted to training-label errors. The schematic does not specify how the offset is estimated or scored.

Try it

Start with x₀ = (4, −1). Block 1 adds (−1, +2). Block 2 adds (+1, 0) if its current second coordinate is positive, otherwise (0, 0). What is the final state? What would you get if you incorrectly evaluated both branches on x₀?

Show the reasoning

Block 1 gives x₁ = (3, 1); the second coordinate is now positive, so Block 2 gives x₂ = (4, 1). If both branches saw x₀, the second branch would see −1, emit zero, and leave (3, 1). Updating the state changed the next edit.

Primary sources: He et al., ResNet; He et al., identity mappings; Vaswani et al., original Transformer (§3.1); Xiong et al., pre-norm vs. post-norm; Friedman, gradient boosting.

Use a residual on a real tensor shape

Four image patches with eight features each give a 4 × 8 matrix. Attention can mix information across the four rows; its output projection returns a 4 × 8 edit. Add it elementwise to the original 4 × 8 matrix. The later MLP may temporarily expand each row to 32 features, but projects back to eight before its own addition. The shortcut does not concatenate features and does not add more tokens.

Why are two residual edits not usually interchangeable?

The second edit sees the state after the first edit. Starting with x = 2, let one edit add 1 and the other multiply the state by 2 by adding the current state. Add then double yields 6; double then add yields 5. Same ingredients, different order.
