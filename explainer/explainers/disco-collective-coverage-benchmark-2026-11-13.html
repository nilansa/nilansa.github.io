Research notebook 01 · Evidence-first

When one memory isn't enough.

A test of whether retrieving different, complementary pieces of evidence works better than simply retrieving the individually most similar messages.

01 · The question

Relevant is not the same as sufficient.

Imagine asking a research assistant: “Is the next software release ready?” The answer may require the latest deployment region, the rollback rule, and the security approval. No single chat message contains all three.

A standard retriever usually scores every message against the question and returns the highest-ranked messages. In a busy project, several messages may repeat the same release detail. The assistant sees three relevant messages but still misses an essential fact.

DISCo (ICLR 2026) studies the alternative: select a set of documents whose token-level representations together cover a complex query. Its official technique uses a dense subset index, successive probes, and iterative editing of the remaining query representation.

The hypothesis. Collective coverage should help most when a question needs several distinct facts, when many similar messages compete for a limited retrieval budget.

Not assumed. DISCo does not automatically know which decision is newest or authoritative. Time and authority are separate experimental factors.

03 · Method distinction

Coverage is different from freshness.

QUESTION COVERAGE

Did we retrieve every distinct ingredient?

A set-valued scoring rule rewards messages that add missing evidence. This is the part DISCo directly addresses.

TEMPORAL CORRECTNESS

Is each ingredient still valid?

An old approval may have been withdrawn. Version tracking and authority resolution are separate from the retrieval coverage objective.

Figure 2. The last authoritative decision can contradict an earlier relevant message. A coverage retriever must be evaluated separately from a temporal filter or conflict resolver.

04 · Dataset blueprint

First build a world. Then generate conversations.

A valid benchmark needs plausible causes for each message. We first define an organization's projects, participants, decisions and event timeline. The dialogues are generated from that latent world, across channels and days. Questions and gold evidence are derived from the same event graph but checked for wording leakage.

Figure 3. Ground-truth event construction prevents arbitrary fact changes and makes updates auditable. Independent realism and evidence checks remain necessary.

05 · Experiment contract

We cannot move the goalposts after seeing the scores.

Every retrieval method receives the same snapshot of the corpus, query and permitted candidate budget. It must not see the answer key. When comparing full document retrieval and short messages, report both message-count and token-budget results.

Primary outcome

Complete evidence @ k: the fraction of answerable questions for which every required gold evidence item is in the retrieved set. This is stricter than merely finding one relevant message.

Secondary: evidence recall@k, precision@k, answer validity, duplicated-topic retrieval, query latency, index build cost and token budget.

How to trust a gain

Use held-out scenario families, paired differences and cluster bootstrap confidence intervals. Pre-register a practically meaningful improvement (for example ten percentage points versus the strongest static baseline), then report the interval, all strata and failures. The target is not an achieved result.

Stop condition: If the model-level dense baseline, alternative valid evidence annotations, or equal token-budget comparison is missing, the pilot can still inform implementation—but cannot establish that DISCo beats strong retrieval systems.

07 · Skeptical checklist

What could make the result misleading?

Template shortcuts

If every query copies the same exact words as its answer, a model may exploit a generator artifact.

Missing valid evidence

One question may have several equally valid evidence sets. A single reference set can unfairly penalize retrieval.

Cheap baselines

Beating TF-IDF alone does not establish success against ColBERT, strong neural retrieval or modern hybrid systems.

  1. Review a stratified sample of generated conversations for realism, contradictory facts, and minimal evidence sufficiency.
  2. Check that scores are stable after independent paraphrasing and distractor resampling.
  3. Report results where collective coverage hurts: one-hop questions, exact-ID lookup, temporally superseded facts, and low retrieval budgets.
  4. Separate objective quality from runtime/index-efficiency claims; exact greedy set selection is not the full DISCo implementation.
  5. Compare against relevant existing benchmarks, rather than claiming that synthetic group conversations are new.
