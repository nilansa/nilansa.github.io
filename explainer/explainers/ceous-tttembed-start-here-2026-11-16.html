01 · Definitions

A query, a document, and one expensive judgment

Query is what somebody asks (for example, “Which study explains why a medication affects sleep?”). A document is one possible answer source, such as a paper abstract or a passage. A query–document pair is the specific combination (this query, this document). A reranker scores that pair to estimate relevance. Ten documents judged for one query = ten rewarded pairs, not ten queries.

Common confusion: ColBERT is not a cross-encoder. It is a late-interaction retriever with separately encoded documents. A cross-encoder jointly processes each query-document pair. “Cross-retriever” is not a standard model name here; use cross-encoder reranker for the expensive teacher and complementary retriever for a second retrieval system.

DISCo ≠ ColBERT ≠ cross-encoder. DISCo uses contextual token representations and a special index to select a set of documents with complementary query-token coverage. Ordinary ColBERT scores each document by MaxSim, while DISCo's set objective rewards information not yet covered by the selected set. Neither is automatically an expensive teacher score.

ColBERT score: S(q,d) = Σᵢ maxⱼ ⟨Qᵢ, Dⱼ⟩ DISCo coverage: F(S,q) = Σᵢ max {⟨Qᵢ,Dⱼ⟩ : d ∈ S, token j in d}

The formulas are schematic; DISCo applies additional transformations/indexing to accelerate successive coverage probes.

02 · Main paper

What TTT-Embed actually optimizes

Chen & Wu, TTT-Embed (2026) keeps the retriever weights, document vectors, and index frozen. It takes scalar rewards from a teacher and learns only a small residual vector v in the existing embedding space. The vector modifies future query vectors, so the next retrieval may find documents outside the initially scored list.

Base: xq = unit(encode_query(q)); zd = unit(encode_doc(d)) score(q,d) = xq · zd Teacher: pT = softmax([r(q,d₁), …, r(q,dₖ)] / τT) Student: pS(v) = softmax([unit(xq + v) · zdᵢ] / τS) Fit: v*g = argmin_v Σ(q in feedback group g) wq KL(pT || pS(v)) + λ ||v||² Deploy: x'q = unit(xq + αg v*g), where αg = ng/(ng+1) Next: Search the FULL unchanged document index with x'q.

Interpretation: the teacher prefers some documents to others; fitting v makes the frozen retriever's scores on the same judged candidates better reflect that preference. Normalizing and adding v changes query-side geometry, not the stored documents. It may also change documents not previously scored, but that benefit must be measured with independent relevance judgments.

Global-wise

One v for all tasks served by a given embedding model. Pool reward evidence across tasks, then apply the same learned state even to unscored future queries and unseen tasks.

Broad sharing · best at very low average reward budgets in the paper.

Task-wise

One v per task (for example, one for FiQA2018). Reward some queries in that task, apply the vector to other, unscored queries in the same task.

Intermediate sharing · strongest for the paper's medium-budget range.

Query-wise

One v per scored query. It needs teacher scores for each particular query to be adapted; unscored queries get no reused state.

Most specific · strongest at the paper's high feedback budgets.

Not three separate datasets: these are three sharing scopes for the same learning rule. The paper tests them on the same 15-task suite and matches the reward pairs within each budget comparison.

03 · Scarce supervision

What “budget 10” means

If there are N test queries and the teacher scores a total of B query–document pairs, the paper defines the normalized reward budget b = B/N. For example, a workload of 1,000 queries with b=10 permits 10,000 teacher scores overall. It does not require scoring exactly ten documents for each query: some queries can be unscored, with rewards pooled for shared scopes.

B = Σ(q rewarded) number_of_scored_documents(q) ; b = B / N

Below are paper-reported gains in nDCG@10 percentage points, averaged equally over 15 MTEB tasks and five embedding models. They are not Ceous measurements. These are three representative operating points; the best scope changes along the full tested budget curve.

04 · Original paper's setup

Which data, retrievers and teacher?

Embedding models (five): Qwen3-Embedding-0.6B, Qwen3-Embedding-4B, EmbeddingGemma-300M, Gemini Embedding 1, and Gemini Embedding 2. They differ in size, pretraining/family, and whether their weights are open (the first three) or accessed by API (the two Gemini models). All produce query/document embeddings; the experiments normalize and search with inner product/cosine. The main teacher is Qwen3-Reranker-4B, with relevance score P(Yes | q,d) calculated from Yes/No logits. The reranker is a feedback source, not one of the five retrievers.

Datasets: fifteen English MTEB retrieval tasks, 12,263 queries and 1,661,208 corpus entries aggregated across task-specific corpora. Categories include fact verification, scientific literature, finance, question answering and duplicates; the paper reports task-macro-averaged nDCG@10. SKILLRET (4,997 queries, 6,660 skill cards) is an additional specialization/forgetting benchmark, not one of the fifteen.

05 · Evidence versus hypothesis

What Ceous actually ran

A · SCIDOCS — query-wise ReFIT completed reproduction attempt

Dataset: 1,000 BEIR SCIDOCS test queries, 25,657 papers. Retriever: frozen Contriever-MSMARCO. Teacher: MiniLM-L6 cross-encoder. Each query physically scored 125 first-stage documents; 100 scores fed 100 ReFIT KL updates, then a second full search.

37.8067% → 37.8717%

Metric: Recall@100. Difference +0.065 percentage points, paired 95% interval [−0.180, +0.325]. Our attempt did not reproduce the published ReFIT 40.1% reference, and detected no reliable improvement.

This is ReFIT, not query-wise TTT-Embed. Do not compare its Recall@100 numerically with the nDCG@10 paper table.

B · FiQA2018 — task-wise TTT-Embed completed cross-fit

Dataset: 648 FiQA test queries, all 57,638 documents. Retriever: frozen Qwen3-Embedding-0.6B (1,024-dimensional vectors). Teacher: cached Qwen3-Reranker-4B Yes probabilities, 10 scored top-ranked pairs per rewarded query.

Protocol: five folds; ~80% rewarded training queries and ~20% unscored held-out queries per fold; five task-wise vectors; all 648 held out once; full-index re-search.

0.46722 → 0.46313

Metric: nDCG@10. Delta −0.00408; paired 95% interval [−0.01072, +0.00262]. Every fold improved in-sample, but no significant held-out gain occurred.

All queries had earlier exposure in development. This is a one-task adapted reproduction attempt, not paper's five-model/15-task average or a fresh blind confirmation.

Key lesson: weak held-out transfer in our tested configuration is a problem to investigate, not proof that task-sharing fails in general. Neither completed experiment tests our complementary feedback selector, and neither demonstrates a new algorithm.

06 · Proposed Ceous question

Can complementary candidates teach a better residual?

TTT-Embed does not optimize which queries and documents are selected for expensive reward scoring; its controlled experiments hold scored pairs fixed across scope comparisons. Our proposed change happens before the teacher: expose different candidate evidence while keeping TTT-Embed's original optimization rule and the same teacher-pair budget.

The expression above is a proposed selection family, not a claimed implementation. When fitting, both teacher and student probabilities are normalized on the same selected slate; candidate pools are selected without reading unseen teacher scores or evaluation qrels. Teacher-score gradients can be inspected afterward to explain why selection helped or hurt, but cannot be used for free to choose which documents to score.

Why this might work: a dense top-10 may contain near-duplicates. A complementary retriever might expose a different concept, which gives the teacher a more informative ordering signal and changes the fitted v. Why it might fail: diverse candidates may be irrelevant; DISCo's token coverage is a set objective, not the same thing as teacher relevance; a single shared vector can express only a limited document-bias pattern.

Must-control baselines

Dense top-k, rank-stratified/random, dense MMR, BM25/RRF, ColBERT candidates, DISCo-inspired coverage (clearly labeled if not official), plus original task-wise TTT-Embed. Compare matched reward pairs when testing optimizer changes; match counts and acquisition costs when testing which pairs to select.

What would count as evidence?

Hold out entirely new queries. Measure independent nDCG@10, Recall@K, docs gained outside original top-B, teacher scores acquired, unique pool size, full-index probes, CPU/GPU cost, latency and paired confidence intervals. First test one task (FiQA); then validate separately on a multi-evidence task such as HotpotQA-HN. No new result is asserted.

Novelty warning: combining methods is not automatically novel. GQR previously used a complementary retriever's scores in a different visual setting; Q-REACT already studies shared query-dependent residuals. The distinct hypothesis here concerns source-aware acquisition of teacher-scored query–document pairs for reusable TTT-Embed state under a fully matched budget.

Our question is not merely “can we move a query vector?” TTT-Embed already can. It is “which scarce feedback pairs should we buy so that a shared correction transfers to queries we did not score?”
08 · Mathematics, explained

Why minimize KL divergence rather than just use the reranker's scores?

Our target is not “make the reranker train itself.” It is “move the retriever's accessible query-side vector so its relative rankings imitate stronger teacher judgments.” The reranker is a fixed external scoring function that may be offered as an API. The learner can be a query vector or a small output-space residual. No teacher weights, activations, attention maps or backward pass are required.

Vector

A list of numbers, such as x = [0.3,0.7,…], representing a query in a common embedding space.

Dot product

x·z = Σⱼ xⱼzⱼ. A fast similarity score between separately encoded query/document vectors. If both have length 1, it equals cosine similarity.

Logit / score

A number aᵢ assigned to a candidate. It need not be a probability and can have a different numeric scale for the teacher and student.

Softmax

Converts a list of scores into positive proportions adding up to 1, preserving their order.

Temperature τ

Divides scores before softmax. Lower temperature = sharper preferences; larger temperature = softer, more even preferences.

Probability distribution

Here: weights on the same candidate slate. They do not assert an 80% chance that a passage is factually correct.

log (natural logarithm)

Measures ratios on a multiplicative scale. KL is measured in nats when the logarithm is natural.

KL divergence

A nonnegative discrepancy between two distributions; KL(P‖Q)=0 when they are identical. It is asymmetric: KL(P‖Q) is generally not KL(Q‖P).

Gradient ∇

A vector of derivatives: for each adjustable coordinate, how would a tiny change affect the loss?

Learning rate η

The size of an update step. Gradient descent moves against the gradient to reduce the loss.

Regularizer λ‖v‖²

A penalty for learning a very large residual vector; λ controls the penalty strength. It can reduce drift, not guarantee better retrieval.

Independent relevance labels

Benchmark qrels are used to compute Recall and nDCG, not to supervise the test-query vector in these methods.

Step 1 — Construct teacher and student preferences

For one query q, choose the same documents d₁, d₂, d₃. Let rᵢ = T(q,dᵢ) be the black-box teacher's scalar output and let aᵢ(x) = (x·zᵢ)/τS be the student's temperature-scaled similarity.

Teacher: pᵀᵢ = exp(rᵢ / τᵀ) / Σⱼ exp(rⱼ / τᵀ) Student: pˢᵢ(x) = exp(aᵢ(x)) / Σⱼ exp(aⱼ(x))

Applying separate softmax normalizations means the teacher and retriever can disagree about their raw numeric scales and still define comparable relative preferences on the same list.

The lowest KL reachable along this particular 4:3 slider path is not zero, because the remaining student weights cannot independently reach the teacher's 3:1 ratio. A learned embedding vector has its own geometric constraints too.

Step 3 — Why KL instead of direct nDCG or recall?

nDCG and Recall depend on a discrete sorted list and independent relevance labels. They are not convenient smooth functions of query-vector coordinates. The teacher instead provides a dense signal for every scored candidate; KL is a differentiable listwise knowledge-distillation surrogate that uses all of those relative scores. For a fixed teacher target, minimizing forward KL(pᵀ‖pˢ) is equivalent, up to a constant, to minimizing the teacher-weighted cross-entropy −Σᵢpᵀᵢ log pˢᵢ.

KL does not directly optimize the true retrieval utility and does not guarantee discovering new relevant documents. It can learn the wrong direction if teacher scores are biased, the selected slate has little useful contrast, or the accessible embedding geometry cannot express the desired ordering.

09 · Runtime optimization

Where exactly does SGD happen if the teacher is black-box?

“Black-box” describes our access to the reranker, not the entire retrieval pipeline. We only ask it for r(q,d). The retriever-side dot products, candidate embeddings and loss function are accessible and differentiable.

Known frozen inputs: document vectors z₁,…,zₖ; teacher targets pᵀ Our variable: x (ReFIT / TOuR per-query) OR v (TTT-Embed residual) Student logits: aᵢ = (x · zᵢ) / τˢ Loss: L = KL(pᵀ ‖ softmax(a)) Derivative: ∂L/∂aᵢ = pˢᵢ − pᵀᵢ Query gradient: ∇ₓL = (1/τˢ) Σᵢ (pˢᵢ−pᵀᵢ) zᵢ SGD update: x_new = x_old − η ∇ₓL = x_old + (η/τˢ) Σᵢ(pᵀᵢ−pˢᵢ)zᵢ

With our toy distributions the three logit derivatives are [−0.50, +0.25, +0.25]. The loss decreases if we raise the first relative logit and lower the other two. This gradient is computed from the student distribution and known document vectors. The teacher never receives a backward pass.

Teacher(q,d₁..dₖ) ──score only──▶ pᵀ [stop-gradient] │ x or v [editable] ──▶ similarities ──▶ pˢ ──▶ KL loss ▲ │ └──────── SGD / Adam on x or v ◀─────────┘ Frozen throughout: reranker θT, encoder θE, document vectors Z, corpus index.
Important access assumption. A black-box teacher API returning scalar scores is enough only if we can also obtain the retriever's query/document vectors and issue a new vector search. A text-only search API that hides all embeddings and accepts only a string query does not automatically permit this update.
For TTT-Embed: x̂_q(v) = unit(x_q + v) L_g(v) = Σ_(q∈feedback group) w_q KL(pᵀ_q ‖ pˢ_q(v)) + λ‖v‖² v ← v − η ∇ᵥ L_g(v) (or an optimizer such as Adam) Deploy x' = unit(x_q + α_g v*)

With unit normalization, differentiating through unit(x+v) requires the chain rule; the simple formula for ∇ₓ above assumes directly optimized, unnormalized dot-product logits. The principle stays the same: gradients stop at the teacher scores, and only query-side state is updated.

Is this “training at runtime”?

Yes, in a limited sense. We are performing genuine gradient-based test-time optimization. But we are not fine-tuning the neural weights of the encoder or reranker. For ReFIT, the updated query vector is typically discarded after that request. For TTT-Embed, task/global residual vectors persist and can serve subsequent unscored queries.

10 · Research hypothesis, not yet a result

How could complementary candidates change the gradient?

The teacher only scores the documents that we select. Look again at the gradient:

∇ₓL = (1/τˢ) Σ_(d∈S(q)) [pˢ(d) − pᵀ(d)] z_d

Every selected document contributes a weighted vector to the gradient. If the slate S(q) consists of near-duplicates, its document vectors may point in similar directions and offer limited independent contrasts. If S(q) includes different kinds of evidence, the gradient can involve different directions that the teacher approves or rejects. That is the mechanism behind our hypothesis; it is not a theorem that more diverse documents are always better.

Original acquisition: S_dense(q) ⊂ Top-B_dense(q), |S_dense(q)| = k Our proposed pool: U(q) = Top-B_dense(q) ∪ C_BM25(q) ∪ C_ColBERT(q) Proposed selector: S_comp(q) ⊆ U(q), |S_comp(q)| = k Compare: v*(S_dense) vs v*(S_comp) using same KL, teacher, k and scope

DISCo-style collective coverage may supply a selection signal that avoids repeatedly covering the same query token. Its native token vectors are not directly added to a Qwen3 single-vector residual; the extra retriever only proposes document IDs, which are then looked up in the frozen target retriever's own document embedding index.

F_coverage(S,q) = Σ_(query token i) max_(d∈S, token j∈d) sim(qᵢ, dⱼ)

A meaningful result would be a controlled improvement in held-out nDCG@10, Recall@K, and judged-relevant documents recovered outside the original pool, while charging the additional BM25/ColBERT/DISCo retrieval work and exactly the same teacher-pair budget. Rank-stratified, random, MMR, direct reranking and deeper dense retrieval are necessary controls. Any gain from simply doing more search must not be falsely attributed to improved teacher supervision.
