Agent memory has two different routing problems

Finding the right memory record and finding the right agent are not the same task. Here is how storage research and multi-agent communication research fit together.

1. Two tracks, two expensive failures

Storage / retrieval track

Question: “Which past fact answers this question?”

Unit: memory item or evidence passage.

Failure: The correct fact is present but missing from the retrieved top 10.

Tools: BM25, vector indexes, filters, entity links, temporal versioning and rerankers.

Natural metric: evidence Recall@10/15 plus lookup/update cost.

Communication / coordination track

Question: “Which agent knows enough to answer or act?”

Unit: agent ownership, capability and message.

Failure: The coordinating agent contacts many irrelevant agents, or misses the one that knows.

Tools: capability directories, ownership summaries, selective routing, hot/cold caches and confidence gates.

Natural metric: task success, message count, latency and total tokens.

Important separation: Better document retrieval does not automatically reduce inter-agent messages. Better routing does not automatically retrieve the correct underlying fact. Measure each layer independently and then end to end.

“ZooKeeper-like” is an analogy

It describes directory/coordination logic. It does not imply that Apache ZooKeeper is running or that consensus protocols are used.

Hot versus cold

A hot cache stores information likely to be used soon; cold memory stores less-frequently-accessed information. Cache hits are useful only if they are correct and not stale.

Do not confuse labels with evidence

Knowing that “database-agent handles schemas” does not establish which historical migration actually broke a deployment. The agent still needs evidence.

3. Try the communication-routing idea

Select a question to see which agent might need to be contacted. This is an illustrative toy scenario, not a benchmark result or a reconstruction of an unpublished system.

What the demo hides

A real router must build and refresh agent summaries; handle transferred ownership, conflicting claims and newly created agents; know when to contact multiple agents; and abstain or broadcast when confidence is low. These all add overhead.

5. Accepted research that overlaps with communication routing

Agent routing and communication-cost optimization already appear in top conferences. A generic “choose the right agent” claim is therefore not sufficient novelty.

  • AgentRouter (ACL 2026, full paper): task-aware knowledge-graph-guided routing of queries among agents.
  • ProtocolBench (ICML 2026): directly measures success, latency, message/byte overhead and failure robustness across agent protocols.
  • MOC (ICML 2026): multi-hop message consolidation under token constraints.
  • Symbolic Communication (ICML 2026): query-adaptive compact protocols, optimizing correctness versus generated tokens.
  • Deployment Trade-offs of Small Models (ACL 2026 industry): documents scenarios in which router coordination costs overwhelm gains.

Research implication: Test the narrower case of time-varying agent ownership of evidence and stale directory state with budgeted correctness, against AgentRouter-style learned and simple directory baselines.

6. Which research track should go first?

A. Strengthen memory retrieval

Best if the main observed failure is right agent, wrong evidence. First compare a strong static retrieval system with query-adaptive variants. See the ADAPTEX DBMS research explainer.

B. Strengthen communication

Best if the main failure is wrong agent, unnecessary broadcast, or stale ownership. Evaluate selective routing against full broadcast, naive directory lookup and learned routing.

C. Cross-layer research

Best only after A and B independently work. The router may choose an agent and a memory path jointly, subject to a total cost budget. The search space is larger and attribution becomes harder.

Tighter communication research statement

Given agents with partially overlapping, changing private histories, can a lightweight, update-aware router identify the smallest sufficient set of agents for a query while preserving end-to-end correctness and reducing total communication cost relative to strong static directory and broadcast baselines?

Falsifiable hypotheses

  1. Non-uniform ownership: Some questions are single-agent, some multi-agent, and some unanswerable. A one-target rule will fail on at least one class.
  2. Routing benefit: A learned or adaptive router maintains answer accuracy while reducing messages or token traffic after including router overhead.
  3. Robustness: Benefit survives changing ownership, cold-start agents, cache staleness and growth in fleet size.
Stop/go rule: If a simple static directory plus a small fallback broadcast matches adaptive routing, retain the simpler system. A new coordination data structure is justified only by a reproducible failure in the existing design.

Suggested controlled experiment

  1. Freeze a set of independent agents and evidence-labelled tasks.
  2. Tag tasks: one-agent, multi-agent, update/temporal, unknown/abstention.
  3. Compare full broadcast, hand-maintained directory, semantic directory and a budgeted query router.
  4. Measure success, messages, bytes/tokens, p95 latency, routing cost and stale-owner error.
  5. Repeat at multiple agent counts and update rates. Test on held-out task types rather than tuning only on one benchmark.
