The highest-value next work is evidence, not a larger LLM

The current solution is a good screening prototype. To make it credible for real Lloyds customers, the first milestone is to measure whether its retrofit estimates correspond to actual outcomes in appropriately matched homes.

P1

Collect a real, consenting before-and-after evaluation set

With proper consent and a separate protected identity-linkage system, collect dated home EPCs, meter readings, heating equipment, retrofit completion and quotes. Define time windows and record weather, occupancy and tariff changes. Report per-fuel savings error, bias, uncertainty coverage and the rate of infeasible recommendations. Compare on the same homes with the existing Lloyds Energy Saving Trust tool, without assuming our prototype will outperform it.

Acceptance: reproducible matched-household evaluation and honest uncertainty.

P2

Replace universal retrofit coefficients with better impact evidence

Use NEED impact-of-measures statistics and other defensible empirical estimates, stratified where possible by dwelling type, baseline demand, climate and actual measure specification. For heating transitions, model electricity and gas separately with measured seasonal performance. For solar, add roof orientation, shade, export and usage timing. Show uncertainty and avoid causal claims unless the study design supports them.

Acceptance: scenario savings errors checked against real held-out outcomes, not just simulator labels.

P3

Enhance the five-feature consumption predictor only with real new features

Candidate features: validated floor area, dated EPC characteristics, occupancy patterns with consent, smart-meter time profiles, heating system age, insulation depth, local climate and known installations. Require source dates prior to target consumption, consistent category mappings, privacy checks and a fresh untouched evaluation set. Compare against simple baselines and current HGB before adding model complexity.

Acceptance: better held-out per-fuel MAE and calibrated uncertainty by region, property type and EPC group.

P4

Expand real-world explanation testing

Recruit representative homeowners to assess understanding, actionability and missing-data communication. Evaluate a held-out bank-style query set: contradictory conditions, negation, unaffordable plans, older homes, underheating, photo uncertainty and unsupported value queries. Record unsupported-claim rate, exact numerical fidelity and response time.

Acceptance: evaluated groundedness rather than relying only on the 13-case synthetic parser suite.

P5

Production integration after model validity

Add versioned data pipelines, secure user accounts and consent, audit trails, schema validation, installer follow-ups, hosted model isolation and cost/latency monitoring. Do not turn a provisional home score into a lending, grant or certified building decision.

Acceptance: audited and monitored service with human oversight, not a local public demo.

Commands a judge can reproduce

Run the frontend + local API
node scripts/server.mjs
# visit http://127.0.0.1:4173

Node.js 22+. The screen and numerical engine work without Ollama. Text models are optional.

Full scripted tests
node --test tests/*.mjs
python3 -m pip install -e '.[test]'
PYTHONPATH=src python3 -m pytest -q

Checked-in evidence reports 70 JavaScript and 32 Python passing tests, plus 11 separate browser interaction cases. This guide did not claim those have been rerun on a fresh judge laptop.

Train with official source CSV
PYTHONPATH=src python3 scripts/train_need.py \
  --data data/raw/need_2026_50k.csv \
  --output results/need_metrics.json \
  --model-dir results/need_models

The CSV is an external government source and intentionally excluded from the source ZIP. Download it separately under its terms.

Optional text model
ollama serve
ollama pull qwen3:4b
# then restart the GreenHome server

The code checks whether a compatible local Ollama model tag exists. No API key is required; the local model is not bundled with the repository.

Precise words you should be able to define

MAE · mean absolute error

The average absolute gap between predicted annual kWh and the held-out observed kWh. Smaller is better; MAE is in the same units as the target.

EPC · Energy Performance Certificate

A building-energy rating system from A (best) to G (worst). The NEED extract groups A/B and F/G, so this app must preserve that imprecision.

Counterfactual scenario

What the calculation says might happen after a selected change, holding other modelling assumptions fixed. It is not an observed outcome.

COP · coefficient of performance

Useful heat output divided by electricity input for a heat pump. The simulator assumes 3; real seasonal COP varies with climate, emitters and operation.

Provisional

Some components lack confirmed evidence or use imprecise proxies. The score can change when real facts are entered.

Calibration

Choosing an uncertainty interval radius using validation errors, then measuring how often held-out observed values fall within the interval.

Final rehearsal question

“If the LLM stopped running, what would the homeowner still get?” Answer without hesitation: “The weighted score, feasibility decisions, selected upgrade packages and every numerical comparison, because those are implemented in deterministic code and the recorded data. The LLM is optional.”
