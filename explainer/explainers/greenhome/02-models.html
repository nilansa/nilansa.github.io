Chapter 02 / The trained models

What the ML really predicts

Two models, five categorical features, a 60/20/20 split and honest held-out results.

Based on actual submitted codeNo invented model capabilitiesOffline reading

One sentence to memorise

“We fit two separate histogram gradient-boosting regression models on anonymised NEED records—one to estimate annual electricity, one for annual gas—using five categorical home descriptors. We use them only when observed energy data is missing.”

Show what “one-hot encoding” means

Suppose the category set learned from training rows contains three types: Flat, Detached and Semi-detached. “Semi-detached” becomes three numerical indicators: Flat=0, Detached=0, Semi-detached=1. This is repeated for the other four features. The model receives these indicators, not the English words.

raw:   { PROP_TYPE:"Semi-detached", REGION:"London", ... }
after: [type_flat=0, type_detached=0, type_semi=1, ...]
target for electricity model: Econs2024 in kWh/year
target for gas model:         Gcons2024 in kWh/year

Only categories observed in training define the feature-column order. A new/unseen category is mapped to the explicit MISSING indicator with a warning—never quietly treated as a new trained category.

Exact training procedure

1

Read the 50,000-row official CSV

Targets: Econs2024 and Gcons2024. Retain for each target only rows marked V with a finite, nonnegative annual kWh value. Electricity and gas masks differ.

2

Freeze one source-row split

60% train, 20% validation, 20% test; train_test_split, random seed 42. The same original row split is reused across fuels before each target's validity filter.

3

Fit encoders and a simple baseline on training only

Baseline = median 2024 consumption by property type and floor-area band. Unseen group → training global median. One-hot categories are also fitted using training rows only.

4

Train three candidate methods per fuel

The grouped-median baseline, histogram gradient boosting with squared-error loss, and the same booster with absolute-error loss.

5

Select by validation MAE—not test

Choose the smallest validation mean absolute error separately for electricity and gas. The absolute-error HGB won for both. A held-out test score is then computed once after selection.

6

Calibrate an interval, save two models

Use the 80th-percentile validation absolute residual as a symmetric radius. Save the estimator, encoder categories, training schema, baseline, split IDs, source hash and metrics in two compressed joblib artifacts.

Plain language

What does boosting do?

It fits a sequence of small decision trees. Each tree helps improve the combined prediction. A histogram implementation groups continuous encoded feature values for efficient splitting. The loss asks the model to reduce absolute prediction error, which aligns with the MAE model-selection metric.

It is not a neural network, transformer, Gemma model, XGBoost run or custom-trained LLM.

Absolute-error boosting won

Electricity validation MAE 1,581.30 kWh/year; gas validation MAE 3,931.42 kWh/year. The model was not chosen by repeatedly trying variants on the test set.

Uncertainty calibration

~80% observed test coverage

Electricity: radius ±2,121.76 kWh, 80.03% test coverage. Gas: radius ±6,019.58 kWh, 78.83% coverage. Lower bounds are clipped to zero.

Do not call these precise household predictions

The absolute errors are large. Dataset fields omit occupancy, appliances, comfort, detailed dwelling fabric and date-verified property attributes. Calibration is descriptive under this split; it is not a guaranteed predictive interval for any future UK household.

The Python predictor is launched as a short-lived local process with a ten-second timeout. It loads existing electricity.joblib and gas.joblib. It does not retrain while serving a request. A confirmed all-electric heating input can set gas to known zero by application rule; this is not a model prediction of zero gas.

For a new feature—for example dwelling insulation grade or measured roof area—we would first need that field for real training homes, recorded at the correct time and with appropriate consent. Then modify FEATURES, update category encoding and request mapping, refit candidates on training rows, select on validation, recalibrate intervals, and compare once on a fresh untouched test set. Merely adding an input box to the UI does not make the trained model understand that feature.

Judge question: “Why not use XGBoost, deep learning or a larger model?”

“We chose a fast, small, reproducible CPU baseline for structured categorical tabular data. We compared multiple candidate losses and a grouped-median baseline. The improvement is modest, so we would not claim algorithmic superiority; better time-aligned building and occupancy features are likely more important than simply increasing model complexity.”
