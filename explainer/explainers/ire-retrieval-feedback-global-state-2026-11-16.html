From query feedback to a global retrieval state

A guided study of TOuR, ReFIT, TTT-Embed and DISCo. It explains why reranker feedback matters, how a query can change at inference time, and how one learned vector can be reused across many queries.

Start with the problem

A dense retriever is fast. It searches a large document collection and returns a short list. A stronger cross-encoder can then score the query and each document together. This second model is more expensive, so it normally sees only the first list.

That creates a limit. If a useful document is outside the first list, the reranker cannot promote it. It never sees that document.

This is a conceptual map, not a claim that the papers form one linear algorithm. TOuR and ReFIT are query-level feedback methods. TTT-Embed studies whether the learned state can be shared. DISCo solves a separate set-retrieval problem.

Division 1 · Main focus

TTT-Embed: learn a correction once, reuse it many times

TTT-Embed asks a different question from query-by-query relevance feedback. Instead of learning a private correction for each query, can a small amount of ranking feedback teach a vector that many future queries can use?

What stays fixed?

Embedding model

Its parameters do not change.

Document vectors

The stored corpus embeddings do not change.

Search index

The existing ANN index stays in place.

What is learned? A small residual vector in the output embedding space. It is stored outside the model.

How the method works

  1. Encode the query and documents with the frozen embedding model.
  2. Choose a limited set of query-document pairs for reward scoring.
  3. Ask a reranker or reward model to score those pairs. The output is a scalar score for each candidate.
  4. Fit a residual vector so the retriever's scores on those candidates match the reward model's ranking distribution.
  5. Add the learned vector to later query embeddings and search the unchanged document index again.
Teacher: pT = softmax(reward scores / teacher temperature)
Student: pS = softmax(query-vector similarity / student temperature)
Learn v by minimising KL(pT || pS) + λ ||v||²
Deploy: corrected query = unit(original query + αg v)
Global/task scale: αg = ng / (ng + 1)

The loss uses the relative scores within each candidate list. It does not require ground-truth relevance labels for fitting. The paper uses those labels only to evaluate the final rankings.

Three ways to share the learned vector

ScopeHow many vectors?Who uses the vector?
Global-wiseOne vector for an embedding modelEvery query served by that embedding model, across tasks
Task-wiseOne vector for each retrieval taskQueries within that task
Query-wiseOne vector for each rewarded queryOnly that query
The focus here is global-wise TTT-Embed. It does not learn one correction per query or one correction per task. It pools reward feedback across tasks, learns one shared vector for the embedding model, and applies that vector to later queries.

What does “generalise” mean in this paper?

The paper defines a workload E. A subset S_B receives reward scores under the available budget. The remaining queries are U_B = E \ S_B. The shared vector is learned from S_B and then tested on queries that did not receive reward scores.

Rewarded queries S_BExamples from several tasks
→
One global vector vLearned outside the encoder
→
Unseen queries U_BReuse the same vector

For the global state, the paper first averages rewarded queries within each task, then averages the tasks equally. This stops large tasks from dominating the shared vector. The paper uses two strict checks. First, 80% of queries provide rewards and the vector is evaluated only on the remaining 20%. Second, leave-one-task-out evaluation learns the global vector on 14 tasks and applies it to the task that was not used for learning.

The result is not that global sharing is always best. The best scope depends on the reward budget. Global sharing is best in the low-budget range tested by the paper. Task-wise sharing is stronger at moderate budgets. Query-wise adaptation is strongest at high budgets. The global result matters because it shows that a vector learned from some tasks can help queries and tasks that did not provide rewards.

What can one global vector learn?

For dot-product retrieval, adding the same vector to every query adds the same document-dependent term to every query's score. In simplified form, the score becomes the original query-document score plus a shared document preference. This gives the system a reusable global correction. It cannot express every query-specific preference. The paper's experiments test whether this shared signal is useful on average and on held-out tasks.

Important boundary: the positive global transfer numbers above belong to the TTT-Embed paper. They do not prove that Ceous has already learned a global vector that generalises. Our own FiQA task-wise cross-fit is a separate experiment and is not a global cross-task test.
Division 2 · A separate retrieval problem

DISCo: choose documents that cover the query together

DISCo (Dense Index for Set Coverage) starts from a different observation. For a complex question, one passage may not contain the full answer. Several passages may need to work together.

Ordinary top-K retrieval scores each document on its own. It can return several documents that repeat the same part of the query. A useful fact may remain uncovered.

Independent top-K

Each document competes on its own score. The top results can repeat the same evidence.

Passage A: person
Passage B: person
Passage C: person

The list may contain strong individual matches but leave one part of the question unanswered.

Collective coverage

The system scores the set. A new document is useful when it covers query information that the current set does not cover well.

Passage A: person
Passage B: place
Passage C: role

The set covers more parts of the information need.

The objective

DISCo represents the query and each document as a set of contextual token vectors. For each query token, the set receives credit for its best match across all selected documents. Repeated coverage does not receive repeated credit.

F(S, Q) = sum over query tokens q of
max similarity(q, any token in any selected document in S)

The system builds the set one document at a time. At each round, it adds the document with the largest marginal gain in coverage. The objective is monotone and submodular, so the greedy method has a (1 − 1/e) approximation guarantee.

Why DISCo needs a new index

A direct greedy implementation would score every document at every selection round. That is too slow for a large corpus. DISCo rewrites the marginal-gain score using augmented vectors, then uses random projections and a multi-vector inverted-file index to support successive approximate-nearest-neighbour searches. The selected set grows after each round, and the next query representation reflects what is already covered.

How DISCo relates to TTT-Embed

DISCo chooses a useful set of documents. TTT-Embed learns a reusable vector from reward scores on selected query-document pairs. They operate at different stages.

Possible connection, not a result: a coverage-based selector could choose which documents should receive expensive reranker feedback. TTT-Embed could then distil those scores into a shared vector. This page records the relationship between the methods. It does not claim that this combined system has been validated.

Project boundary: the separate Ceous H8 pilot used a simplified greedy coverage selector over a fixed dense top-50 candidate pool. It was not an implementation of the official DISCo multi-vector index. Its experimental outcome is kept out of this paper-level explanation.

Division 3 · Query-level precursors

TOuR and ReFIT: learn from feedback for the current query

TOuR and ReFIT study how a reranker can help the retriever after the first retrieval. Both work on an individual test query. They do not learn one vector that is shared across tasks.

TOuR: optimise the query itself

TOuR obtains the top-K contexts for one test query. A cross-encoder scores those contexts. The method converts the scores into hard or soft pseudo-labels, then uses gradient descent to update the query representation. After each update, it retrieves again and scores the new candidate list. The query and context encoders stay fixed; the method changes only the current query vector.

One test queryInitial query vector
→
Top-K contextsRetrieve candidates
→
Cross-encoderMake pseudo-labels

TOuR showed that query-side optimisation can improve phrase retrieval and open-domain question answering. It also studied hard-label and soft-label versions. The update is private to the query being processed.

ReFIT: distil the reranker's ranking, then search again

ReFIT identifies a limit in the usual retrieve-and-rerank pipeline. The reranker can improve the order of the retrieved candidates, but it cannot improve Recall@K if it only sees the original top-K list.

ReFIT distils the reranker's predictions for the current query into the retriever's query representation. It then runs a second retrieval with the updated query vector. The second search can return documents that were not in the first candidate list.

Ceous · Completed reproduction attempt

What we ran: ReFIT on SCIDOCS

We ran the public ReFIT method on the original BEIR SCIDOCS test split. This is a reproduction attempt. It is not a new method.

Dataset

1,000 test queries
25,657 documents
4,928 positive query-document judgments

Frozen models

Retriever: facebook/contriever-msmarco
Teacher: cross-encoder/ms-marco-MiniLM-L6-v2

Pipeline used in the run

  1. Retrieve the first 125 candidates for each query.
  2. Score those candidates with the frozen MiniLM cross-encoder.
  3. For ReFIT, use the first 100 teacher scores for 100 KL updates. The learning rate is 0.005 and the teacher temperature is 2.
  4. Search the full 25,657-document corpus again with the updated query vector.
  5. Use qrels only after retrieval, to calculate Recall@100.

Four disjoint 250-query shards ran sequentially on Mac MPS. The run computed 125,000 teacher pair scores. ReFIT used 100,000 of them; the rerank-125 comparison used all 125,000.

Results: Recall@100

37.8067%Raw Contriever · paper reference 37.8%
38.3450%MiniLM rerank-125 comparator · paper reference 38.3%
37.8717%Our ReFIT run · paper reference 40.1% at 100 updates

The 40.1% reference is the ReFIT appendix result at 100 updates. The paper's main setup uses 1,000 updates at learning rate 0.001 and reports 40.0%. Our run used 100 updates at learning rate 0.005. The update count matches the appendix setting, but the learning rate differs, so this is not a strict reproduction. The rerank-125 result is a comparator. It is not a separate downstream ranking objective. All three values use the same Recall@100 metric and qrels.

Query-level comparison

In 5,000 paired bootstrap resamples, ReFIT minus raw Contriever was +0.065 percentage points, with a 95% interval from −0.180 to +0.325. There were 22 improved queries, 19 worsened queries and 959 ties.

The rerank-125 comparator was +0.538 points over raw retrieval, with a 95% interval from +0.070 to +1.003. ReFIT was −0.473 points below rerank-125, with a 95% interval from −0.912 to −0.037.

ReFIT returned 100 document IDs outside the initial top-125 lists across 68 queries. None of these newly retrieved documents was judged positive in the SCIDOCS qrels.

Interpretation: the run completed, but our ReFIT result does not reproduce the paper's 40.1% at 100 updates. The measured gain over raw retrieval is small, and its confidence interval includes zero. This is an unresolved reproduction gap. It is not evidence that ReFIT is ineffective, and it is not a Ceous improvement claim.

The next check for this reproduction is source fidelity: preprocessing, embedding pooling and normalisation, candidate depth, teacher-score normalisation, update objective and tie handling. We will not tune against the test qrels.

Part I · Handover

What this first part establishes

Established background

  • The Microsoft challenge asks how reward-model feedback can improve retrieval through post-training.
  • TOuR and ReFIT use feedback to update the current query.
  • TTT-Embed studies a reusable state, including a global vector.
  • DISCo selects document sets for collective query coverage.

Completed Ceous work

  • A full 1,000-query SCIDOCS ReFIT reproduction attempt.
  • Raw, rerank-125 and ReFIT Recall@100 measurements.
  • Paired query bootstrap intervals and an honest report of the reproduction gap.
  • A clear boundary between the paper results and our own results.

Claims we should not make

  • Do not say that Ceous improved ReFIT or reproduced the paper's 40.1% result.
  • Do not describe the H8 coverage selector as an official DISCo implementation.
  • Do not present the TTT-Embed paper's global transfer numbers as our own experiment.
  • Do not say that global sharing is always best. The TTT-Embed paper shows that the best scope changes with the reward budget.

Suggested study order before recording

  1. Read the global TTT-Embed section. Make sure the difference between a shared vector and a per-query vector is clear.
  2. Read DISCo. Focus on why a set of documents can be better than the top-K individual documents.
  3. Read TOuR and ReFIT. Focus on the problem with the first candidate list and why the second retrieval matters.
  4. Review the SCIDOCS table. State the negative result exactly as measured.

This is Part I only. It records the background, methods and completed reproduction attempt. It does not propose the next research method or interpret separate exploratory signals.
