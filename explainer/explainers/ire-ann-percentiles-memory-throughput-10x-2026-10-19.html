This page explains the parts that were still unclear. It uses simple technical English. It also uses small pictures made with boxes.

1) HNSW: what are efSearch, nprobe, and “probe”?

First, do not mix two different ANN families

HNSW
Graph-based ANN index. Common knob: efSearch.
IVF / IVFFlat / IVF-PQ
Cluster-based ANN index. Common knob: nprobe.

Important: efSearch belongs to HNSW. nprobe belongs to IVF. They are not the same parameter.

Generic meaning of “probe”

A probe means: “how many candidate places do I inspect at query time?”

More probing usually gives better recall. But it also gives higher latency.

HNSW idea

Query vector
→
Enter graph
→
Walk to better neighbors
→
Keep a candidate list
→
Return top results

efSearch = size of the candidate list during search.

If efSearch is small, search is fast, but it may miss good neighbors.

If efSearch is large, search explores more, so recall improves, but latency increases.

Simple picture: imagine you are exploring a city map. efSearch is like the number of streets you are willing to examine before you stop.

IVF idea

Query vector
→
Find nearest clusters
→
Search only some clusters
→
Score vectors inside them

nprobe = number of clusters to search.

If nprobe = 1, you inspect one cluster only.

If nprobe = 10, you inspect ten clusters.

So, for IVF, “probe more clusters” = higher recall, but more time.

HNSW knob

efSearch

How many candidates the graph search keeps alive.

IVF knob

nprobe

How many coarse clusters are searched.

Trade-off

↑ search breadth

Better recall, but more latency and CPU work.

2) What does 98th or 99th percentile mean?

Your current interpretation is close, but one detail is wrong.

p99 latency means: 99% of requests finished in at most this time.

Only the slowest 1% were slower.

It does not mean “average of 99 requests”. It is not an average. It is a threshold.

p50

Median

Half faster, half slower.

p95

95% at or below this time

Worst 5% are slower.

p99

99% at or below this time

Worst 1% are slower.

Small example: Suppose you have 100 request latencies, sorted from fast to slow. Then p99 is approximately the latency around the 99th request in that sorted list. It is a boundary, not a mean.

MetricQuestion it answers
Average latencyWhat is the mean time across all requests?
p50What is a typical request time?
p99How bad do almost-all requests get, ignoring the slowest 1%?

3) Index size, resident memory, and total RAM

This is the most common confusion. Think of three different levels.

Total RAM of the machine

This is the full physical memory in the computer. Example: 64 GB RAM.

Resident memory of your process

This is the part of RAM that your running Python process is actually holding in memory right now.

Objects inside the process

Examples: FAISS index, Python dictionaries, NumPy arrays, model weights, buffers, temporary arrays.

Index size on disk

This is the saved file size if you serialize the index. It lives on storage, not directly in RAM.

Index size

Usually a file size.

Example: faiss.index is 44 MB on disk.

Resident memory (RSS)

RAM currently occupied by the process.

Example: after loading the index, your process RSS increases by 70 MB.

Total RAM

Memory capacity of the whole machine.

Example: laptop has 64 GB RAM total.

Why are index size and resident memory different?

  • The index file on disk may be compressed or stored in a compact format.
  • When loaded, extra objects may be created.
  • Python adds overhead for objects and containers.
  • Temporary arrays and buffers also consume RAM.
  • The process also holds code, libraries, and other data, not only the index.

Good viva sentence

“Index size is the stored artifact size. Resident memory is the RAM used by the running process after loading it. Total RAM is the machine capacity. They are related, but they are not equal.”

4) What is throughput in impressions per second?

An impression is one ranking request. It usually means: one user context plus the candidate articles that must be scored and ranked.

One impression arrives
→
Read user/history
→
Retrieve candidates
→
Build features
→
Score + rank

Throughput = how many full impressions the system finishes per second.

If throughput is 200 impressions/s, then the system finishes about 200 ranking tasks per second.

If the system is purely sequential, a rough time per impression is:

time per impression ≈ 1 / throughput

So, at 200 impressions/s, average sequential time is about 0.005 s = 5 ms per impression.

But note: in real systems, throughput and latency are not exact inverses, because of batching, concurrency, queues, and cache effects.

5) How do I estimate cost per 1,000 impressions (or “pages”)?

Use the machine cost and the throughput.

cost per 1000 impressions = hourly machine cost × 1000 / (throughput × 3600)

Example

  • Hourly machine cost = $0.50/hour
  • Throughput = 287.44 impressions/s
impressions per hour = 287.44 × 3600 = 1,034,784
cost per 1000 impressions = 0.50 × 1000 / 1,034,784
                           ≈ $0.000483 per 1000 impressions

That is about 0.0483 cents per 1,000 impressions.

If your quiz says “pages” instead of “impressions”, be careful. Ask: does “page” mean a web page, a request, or an impression? In your ranking pipeline, the closest unit is usually the impression.

6) What will break at 10×?

This depends on what became 10× larger.

A) 10× more impressions, same catalog

  • CPU time for retrieval and feature building increases about 10×.
  • Queueing delay rises if you do not add parallelism.
  • Output writing and logging also grow.
  • p95/p99 latency can worsen under load.

Main bottleneck: online serving throughput.

B) 10× more articles, same request rate

  • Index build time increases.
  • Index file size increases.
  • Resident memory increases after load.
  • ANN recall/latency trade-offs become harder.

Main bottleneck: memory and retrieval structure size.

Very good viva answer

“At 10× load, I first ask what is scaling: requests, catalog, or per-request candidate count. If requests scale, the first failure is often queueing and p99 latency. If catalog scales, the first failure is often memory, index build cost, and retrieval latency.”

7) One clean summary you can say aloud

“In HNSW, efSearch controls how many candidate neighbors the graph search keeps during query time. In IVF, nprobe controls how many clusters are searched. Larger values improve recall, but increase latency. p99 latency is a threshold, not an average: 99% of requests finish within that time. Index size is the stored artifact size; resident memory is the RAM used by the running process; total RAM is the machine capacity. Throughput in impressions per second is the number of full ranking requests the system finishes each second. Cost per 1,000 impressions is computed from hourly machine cost and throughput. At 10× scale, the first failure depends on what scaled: requests usually stress serving latency and queues, while catalog growth stresses memory, index size, and retrieval cost.”
