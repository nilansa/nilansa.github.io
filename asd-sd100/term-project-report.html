Retrieving sufficient evidence under a limited budget

A short proposal based on two completed exploratory research tracks. This is not a claim of a new state-of-the-art method or a successful controlled pilot.

1. Why is this important?

In multi-hop question answering, the highest-ranked passage may explain only half the answer. A system needs a small set of passages that jointly supports its answer, without wasting retrieval time, context tokens or verification calls. A cheaper retriever would also be useful, but only if expensive teacher feedback improves it beyond ordinary gold-label training.

2. What has already been tried?

DISCo (ICLR 2026) retrieves a fixed-size set to cover dense query-token embeddings; this is not the same as proving answer sufficiency. SetR (ACL 2025) already selects evidence jointly. BEAR (EMNLP 2026) already allocates a limited evidence context. HALT and VRR already use verification to stop or revise retrieval. Therefore, simply combining 'coverage', 'budget' and 'verification' is not enough for novelty. Teacher distillation and selective labeling also have substantial prior art; more teacher scores are not automatically better training signals.

3. Our research question and possible contribution

Main direction (P5): Can a qrel-blind retriever select jointly sufficient evidence more accurately than strong existing methods when the same number of passages, actual context tokens, latency and verifier calls are allowed? First measure whether gold-support recall tracks answer correctness. A new adaptive selection rule is justified only if the controlled baselines leave a reproducible failure pattern. This is a hypothesis, not demonstrated novelty.

Separate direction (P1, full-gold STOP; low-gold PARK): Does teacher-scored post-training improve a compact dense retriever when gold-only and gold-plus-teacher arms see the same training queries, optimization steps and total teacher-token budget? Full-gold gates failed; a 5 Nov archive review found the proposed validation diagnostic infeasible. The low-gold comparison remains exposure-confounded. Do not combine both topics into one claimed contribution.

The MuSiQue sample was SHA256-stable, with two gold support passages per question. Retrieval used a frozen, DEV-derived 21,100-paragraph corpus. This is a small closed-corpus test, not open-corpus RAG. Sampling required two gold supports, but the retriever did not read qrels; qrels were used for evaluation. Exact question-overlap checks do not rule out paraphrase or pretraining contamination. The 95% CIs in P1 mainly bootstrap questions after averaging three seeds, so they do not capture full training-seed uncertainty.

5. Plan, threads and resources

First, keep the 150-question sample and corpus frozen; verify identical document IDs and qrel-blind retrieval. Compare an appropriate strong BM25 baseline, ColBERTv2/PLAID and official DISCo at K=2, 3 and 5. Do not run DISCo's original qrel-reading loader unmodified. Next, measure complete support, context tokens, query latency, index memory and—in a later fixed-reader evaluation—answer correctness under matched budgets. Use paired question bootstrap (1,000 resamples) and record failures separately for comparison and bridge questions. Evaluate a truly untouched holdout only after the method and analysis are frozen.

The existing CPU baseline required no GPU, LLM or teacher calls (roughly 30 ms/query in a single local timing run). The frozen Stage-2 CPU feasibility gate failed after 5,400 seconds on 2 November. Its protocol prohibits GPU fallback, so a new, separately approved feasibility plan is required before any indexing retry. No DISCo, reader, or teacher run has followed. No new P1 teacher training is justified without exposure-matched controls and a written protocol.

Decision now: P1 original teacher-budget method — NO-GO. P5 controlled evidence-sufficiency study — CPU indexing feasibility BLOCKED, no comparison verdict. Stop if strong controls eliminate the effect or costs outweigh any answer-quality gain.
